# Тестовое задание: Playable Ad (Spot the Difference)

Проект выполнен в рамках тестового задания для **Azur Games**. 

Основной упор при разработке был сделан на экстремальную оптимизацию веса проекта, производительность, безупречную адаптивность UI и поддержание строгой, интуитивно понятной иерархии сцены и файловой системы.

## 🛠 Технические характеристики
* **Версия Unity:** 2021.3.27 (согласно ТЗ)
* **Размер итогового WebGL билда:** ~3.51 MB
* **Целевые платформы:** Mobile WebGL (iOS / Android)

## 🚀 Ключевые архитектурные решения

### 1. Адаптивная верстка (Responsive Layout)
Проект нативно поддерживает как вертикальную (Portrait), так и горизонтальную (Landscape) ориентации без обрезки ключевого контента. 
* Реализована система жестко закрепленных хедера и футера (Fixed Header/Footer).
* Игровое поле динамически масштабируется в оставшемся пространстве с помощью `Aspect Ratio Fitter`, гарантируя, что арт не искажается и не растягивается при смене ориентации девайса.

### 2. Экстремальная оптимизация (Zero-Bloat)
Чтобы уложиться в жесткие лимиты рекламных сетей и добиться размера билда в 3.51 MB, были приняты следующие решения:
* **UI Particle Burst:** Вместо использования тяжеловесной встроенной системы частиц Unity (которая добавляет лишние шейдеры и вес), эффекты клика и разлетающихся частиц написаны математически через корутины и UI Images. Это стоит 0 дополнительных Draw Calls при использовании атласов.
* **Procedural Animations:** Туториал (рука) и "пульсации" элементов анимированы процедурно (с использованием `Mathf.Sin` и кастомной математики упругости `ElasticOut`). Это позволило полностью отказаться от использования окон Animation/Animator и сэкономить сотни килобайт.
* **Таймер на спрайтах:** Отказ от TextMeshPro в пользу горячей замены легковесных спрайтов с цифрами (0-9) для работы таймера.

### 3. Задание со звездочкой (Анимация окружения)
Анимация деталей локации реализована поверх "сплюснутого" (flattened) фона. Это позволило добавить игре динамики, не разбивая весь задник на десятки отдельных слоев, тем самым сохранив минимальное количество Draw Calls. Анимированные элементы ("наклейки") корректно масштабируются вместе с основным артом при повороте экрана.

### 4. Эталонная иерархия и структура проекта
Внимание к деталям сохранено не только в коде, но и в организации рабочего пространства:
* Иерархия сцены строго разделена на логические блоки: `UI_Header`, `Game_Board_Layout` и `UI_Footer`. Никаких лишних или пустых объектов.
* Файловая система очищена от вложенных дубликатов и мусора. 
* В репозиторий загружены только необходимые исходники (папки Library, Temp, Logs и кэш исключены).

## 📂 Структура проекта (Assets/)
* `Import/` — Оптимизированные и упакованные спрайты, графика.
* `Prefabs/` — Заготовленные UI-элементы и эффекты.
* `Scenes/` — Основная и единственная сцена Playable Ad.
* `Scripts/` — C# скрипты (Layout-контроллеры, логика таймера, процедурные анимации, эффекты).
